# תכנון: צור מבחן (מתקדם) + תמלולים ותיוג

## חלק א — מסך "צור מבחן" (עדכון והרחבה)

### 1.1 התנהגות כניסה

- לחיצה על "תרגול" בתפריט → מסך "צור מבחן" (לא תרגול חופשי ישירות).
- ברירת מחדל: `practiceMode: 'create'`; לחיצה על "תרגול חופשי" → `practiceMode: 'free'` + TraineePracticeSession.

### 1.2 שדות טופס "צור מבחן" (מלאים)


| שדה                   | תיאור                                                           | הערות                                                                                   |
| --------------------- | --------------------------------------------------------------- | --------------------------------------------------------------------------------------- |
| **קטגוריות**          | ריבוי בחירה (כמה קטגוריות)                                      | רשימת קטגוריות מ־getFilterOptions().categories                                          |
| **שאלות מכל קטגוריה** | לכל קטגוריה שנבחרה: שדה מספרי "כמה שאלות מקטגוריה זו"           | אופציונלי: סכום אוטומטי = סה"כ שאלות במבחן                                              |
| **רמות קושי**         | בחירה כמה שאלות מכל רמה                                         | קל / בינוני / קשה — שדה מספרי לכל רמה (או חלוקה אוטומטית)                               |
| **הגבלת זמן**         | בחירה: עם/בלי הגבלה; אם עם — חישוב אוטומטי לפי 1.5 דק׳ לכל שאלה | **הערה למשתמש:** "הגבלת הזמן: 1.5 דקות לכל שאלה שנבחרה." (להצגה מתחת לשדה או ב־tooltip) |
| **נושא**              | רשימה נפתחת (אופציונלי)                                         | filterOptions.topics                                                                    |
| **תגיות**             | ריבוי בחירה                                                     | רשימת תגיות קיימות                                                                      |
| **כפתורים**           | "התחל מבחן" (ראשי), "תרגול חופשי" (משני)                        | כמו בתוכנית הקודמת                                                                      |


### 1.3 לוגיקת יצירת המבחן

- לפי קטגוריות נבחרות + מספר שאלות per category: לאסוף עד X שאלות מכל קטגוריה (מהמאגר הפעיל).
- לפי רמות קושי: לאסוף עד Y קל, Z בינוני, W קשה (או לחלק את סה"כ השאלות).
- שילוב: לאחד את כל השאלות שנבחרו, לערבב אקראית, לחתוך לסה"כ המבוקש אם צריך.
- זמן: אם "עם הגבלת זמן" — `timeLimit = 1.5 * questionCount` דקות (להצגה למשתמש בהערה).

### 1.4 קבצים (חלק א)

- [pages/TraineeDashboard.jsx](pages/TraineeDashboard.jsx) — state `practiceMode`, טופס מורחב (קטגוריות מרובות, שאלות per קטגוריה, שאלות per קושי, הגבלת זמן + הערה 1.5 דק׳).
- [workflows/testGenerator.js](workflows/testGenerator.js) או workflow חדש — פונקציה שמייצרת מבחן לפי: רשימת קטגוריות + מספר per קטגוריה, חלוקת קושי, סה"כ.
- [components/MockExam.jsx](components/MockExam.jsx) — קבלת פרמטרים (כולל timeLimit מחושב), טעינת שאלות עם סינון.
- [App.jsx](App.jsx) / router — העברת state ל־/mock-exam.

## חלק ב — תמלולים (תמלילי שיעורים)

### 2.1 דרישה כללית

- העלאת תמלולים: כל תמלול בקובץ נפרד (למשל ~400 קבצים). פורמט לדוגמה: SRT (כמו "המערכת האנדוקרינית חלק ב.srt").
- המערכת עוברת על **כל השאלות** באתר ומתאימה כל שאלה לתמליל (אם קיים).
- **כל שאלה חדשה** שמוספת עוברת את אותו תהליך התאמה.
- תוצאה: שאלה שמתאימה לתמליל מקבלת **תג עם שם התמלול** (בנוסף לתגיות הקיימות); שאלה שלא נמצא לה תמליל — תג **"לא נמצא בתמלול"**.
- סינון: אפשר לסנן לפי תמליל (לפי שם תמליל) ולפי "לא נמצא בתמלול".

### 2.2 אחסון תמלילים

- **מאגר תמלילים:** מודל MongoDB חדש (למשל `Transcript`) — שדות: `name` (שם תמליל, למשל משם הקובץ), `fullText` (טקסט מלא מחולץ מה־SRT), `originalFilename`, `uploadedAt`.
- **העלאה:** אנדפוינט (למשל POST /api/transcripts/upload) — קבלת קובץ SRT, פרסור, שמירת מסמך ב־DB. תמיכה בהעלאה מרובה (מספר קבצים בפעם אחת או העלאה חוזרת).

### 2.3 פרסור SRT

- קריאת קובץ SRT, דילוג על שורות תזמון (00:00:00,000 --> ...), איסוף שורות הטקסט בלבד ואיחוד ל־`fullText` אחד (לנורמליזציה: רווחים/שורות לפי צורך).
- שמירת שם התמליל: משם הקובץ (ללא .srt) או שדה נפרד בהעלאה.

### 2.4 התאמת שאלה לתמליל

- **אלגוריתם:** לכל שאלה — חיפוש האם `question_text` (או גרסה מנורמלית) מופיעה בתוך `fullText` של תמליל. אופציונלי: בדיקה גם שהתשובה הנכונה (טקסט האופציה) מופיעה באותו תמליל.
- **תדירות:** (א) ריצה על כל השאלות לאחר העלאת/עדכון תמלילים; (ב) עם הוספת שאלה חדשה — הרצת התאמה רק עבור השאלה החדשה (ו־API עדכון תגיות).
- **תיוג:** אם נמצא תמליל תואם → הוספת תג עם **שם התמלול** ל־`tags` של השאלה (בלי למחוק תגיות קיימות). אם לא נמצא → הוספת תג **"לא נמצא בתמלול"**.

### 2.5 ממשק העלאת תמלילים

- **מיקום:** אזור מדריך/מנהל — למשל בעמוד ייעודי "העלאת תמלילים" או בתוך ניהול תוכן.
- **פונקציונליות:** העלאת קבצי SRT (בודד או מרובה), רשימת תמלילים שהועלו, כפתור "הרץ התאמה לכל השאלות" (אם לא אוטומטי אחרי העלאה).

### 2.6 סינון לפי תמליל

- במסכי שאלות (ניהול שאלות, צור מבחן): רשימת תגיות תכלול את שמות התמלילים ואת "לא נמצא בתמלול"; המשתמש יוכל לסנן לפי תמליל מסוים או לפי "לא נמצא בתמלול".

### 2.7 קבצים (חלק ב)

- **שרת:** מודל [models/Transcript.js](models/Transcript.js) (חדש); [server/transcriptApi.js](server/transcriptApi.js) (חדש) — upload, list, אולי delete; פרסור SRT בצד שרת או שיתוף עם קליינט.
- **שרת:** [server/questionApi.js](server/questionApi.js) או workflow — פונקציה "התאמת שאלה לתמלילים" + עדכון תגיות בשאלה; קריאה אוטומטית בעת הוספת שאלה (או גריפה מקצה ייבוא שאלות).
- **קליינט:** קומפוננטת העלאת תמלילים (עמוד או אזור בהגדרות/מדריך); שילוב תגיות תמליל ב־TagFilter / סינון שאלות קיים.
- **מאגר:** [models/Question.js](models/Question.js) — כבר תומך ב־tags (מערך מחרוזות); אין שינוי סכמה נדרש לתג "שם תמליל" או "לא נמצא בתמלול".

## רשימת תיוג מלאה — לאישור לפני ביצוע

להלן רשימת תיוג מלאה. סמן/אשר את מה שמתאים ואפשר לצאת לדרך.

### א. מסך "צור מבחן" — כניסה ומבנה

- **א.1** לחיצה על "תרגול" בתפריט מציגה מסך "צור מבחן" (לא ישירות תרגול חופשי).
- **א.2** state `practiceMode`: ברירת מחדל `create`; כפתור "תרגול חופשי" מעביר ל־`free` ומציג TraineePracticeSession.
- **א.3** כפתור "התחל מבחן" מעביר לבחינה מדומה עם כל הפרמטרים שנבחרו (ניווט + state).

### ב. שדות טופס "צור מבחן"

- **ב.1** בחירת **כמה קטגוריות** (ריבוי קטגוריות).
- **ב.2** לכל קטגוריה שנבחרה: שדה **"כמה שאלות מקטגוריה זו"** (מספר שאלות per category).
- **ב.3** שדות **כמה שאלות מכל רמת קושי** (קל / בינוני / קשה).
- **ב.4** **הגבלת זמן:** אפשרות לבחור עם/בלי; אם עם — חישוב אוטומטי: 1.5 דק׳ לכל שאלה.
- **ב.5** **הערה למשתמש:** הצגת המשפט "הגבלת הזמן: 1.5 דקות לכל שאלה שנבחרה." (מתחת לשדה או ב־tooltip).
- **ב.6** שדות אופציונליים: נושא, תגיות (כולל תגיות תמליל בהמשך).

### ג. לוגיקת יצירת המבחן MockExam

- **ג.1** פונקציה/workflow שמייצרת מבחן לפי: קטגוריות + מספר שאלות per קטגוריה, חלוקת קושי, סה"כ שאלות.
- **ג.2** MockExam מקבל פרמטרים (questionCount, timeLimit, filters) וטוען שאלות בהתאם; timeLimit משמש טיימר במבחן.
- **ג.3** Router/App מעבירים state ל־/mock-exam (questionCount, timeLimit, hierarchyFilters, tagFilters, breakdown per category/difficulty אם רלוונטי).

### ד. תמלילים — אחסון והעלאה

- **ד.1** מודל Transcript ב־MongoDB: name, fullText, originalFilename, uploadedAt.
- **ד.2** אנדפוינט העלאת קובץ SRT (בודד או מרובה); פרסור SRT לחילוץ טקסט מלא ושמירה ב־DB.
- **ד.3** ממשק העלאת תמלילים (עמוד/אזור למדריך): העלאת קבצים, רשימת תמלילים שהועלו.

### ה. התאמת שאלות לתמלילים

- **ה.1** לוגיקה: בדיקה לכל שאלה האם `question_text` (או גרסה מנורמלית) מופיעה ב־fullText של תמליל; אופציונלי: בדיקה שהתשובה הנכונה מופיעה באותו תמליל.
- **ה.2** שאלה שנמצא לה תמליל → הוספת תג **שם התמלול** ל־tags (בנוסף לתגיות הקיימות).
- **ה.3** שאלה שלא נמצא לה תמליל → תג **"לא נמצא בתמלול"**.
- **ה.4** הרצה על **כל השאלות** לאחר העלאת/עדכון תמלילים (כפתור "הרץ התאמה" או אוטומטי אחרי העלאה).
- **ה.5** **כל שאלה חדשה** שמוספת עוברת התאמה לתמלילים (עדכון תגיות) — אינטגרציה ב־create question / ייבוא שאלות.

### ו. סינון לפי תמליל

- **ו.1** במסכי סינון שאלות (ניהול שאלות, צור מבחן): תגיות כוללות את שמות התמלילים ואת "לא נמצא בתמלול".
- **ו.2** אפשרות לסנן לפי תמליל מסוים ולפי "לא נמצא בתמלול".

### ז. נגישות ו־RTL

- **ז.1** שמירה על RTL ו־aria-labels בטפסים ובכפתורים החדשים.
